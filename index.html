How it works

From a link to a pull request, with a test at every step

Cheap checks run first. Agents only look where the graph and the scanners point, and nothing reaches you until it has been reproduced.

01

Map the repo

Clone at one commit in a sandbox, run tests and scanners, and build a graph of files, symbols, calls and covering tests.

02

Plan the hunt

A supervisor reads a 2k-token summary and splits the work into scoped tasks with strict briefs and budgets.

03

Specialists search

Regression, security, leaks, bugs and improvements agents each see only their slice of the graph.

04

Reviewer proves it

Every finding is reproduced with a test in the sandbox. Unconfirmed ones are labelled and never auto-fixed.

05

You approve the fix

A failing test, a small patch, the full suite green and a code review. Approve it and FixIt opens the PR.

The agent team

A supervisor and five specialists, each with one job

Specialists never talk to each other. Every hand-off is a typed object, so each agent's context stays small and auditable.

Supervisor

Reads the repo summary and scanner results, plans up to 12 scoped tasks, then ranks the verified findings into one report by severity × confidence − fix effort.

strong modelread-only graph

Regression

Compares changed symbols with the base branch and the tests that touch them.

Security

Follows bandit, semgrep and pip-audit hits through the graph to real entry points.

Leaks

Unclosed sessions and files, and secrets that end up in logs.

Bugs and logic

Off-by-ones, wrong comparisons and type errors the checkers hint at.

Improvements

Duplication and slow queries, as suggestions. Never fixed automatically.

Reviewer

Sees one finding and how to run the tests, never the specialist's reasoning.

Proof, not claims

A failing test before the fix. A green suite after it.

Success means the new test passes, the existing suite still passes, the diff stays small and in scope, and a human approved it.

Safety and privacy

Code written by a model, run on code written by strangers, treated as hostile

Everything that plain code can check stays plain code: tests, diff size, allowed commands and permissions.

A sandbox per run

Non-root Docker container, read-only base, CPU and memory limits, no network except the package mirror and git host. Destroyed after the run.

Command allowlist

pytest, npm test, grep, ls, git diff. Agents never hold your GitHub token; only the final PR step does.

Diff guard

Caps files and lines changed. No edits to CI, lockfiles or secrets. Tests may be added, never deleted or weakened.

Your data stays yours

Every query is filtered by organization, and Postgres row-level security enforces it again. No user can see another's runs or code.
